# 模板演进流程

最后更新：2026-07-14 01:35 (Asia/Shanghai)

本流程用于把论文、书稿、技术指南或学习者讲义中的真实需求转化为稳定公共能力，同时避免把单一项目的业务语义和私有内容带入包。

## 1. 真实需求进入

- 从可编译的真实消费者出发，先记录编译器版本、命令、页数和必要的视觉基线。
- 只读取与迁移直接相关的入口和依赖，不复制正文、身份字段或项目资源到本仓库。
- 外部工作区保持只读，直到 API 方案和修改范围得到确认。

## 2. 语义归类

逐项判断需求属于哪一层：

- 两类以上文档稳定复用的内容语义进入核心组件。
- 单一 profile 的可复用能力进入对应扩展。
- 封面、目录、页眉页脚和页面结构由 profile 负责。
- 颜色、字体、间距和边框由主题 token 负责。
- 课程字段、组织流程和旧接口兼容留在消费者适配器。
- 项目图片、Bib、CeTZ 图形和其他资源继续由调用项目拥有。

## 3. 中性最小复现

- 在 `examples/` 或 `tests/` 中构造不含真实课程、身份和私有素材的最小复现。
- 最小复现只覆盖待决策能力及其关键边界，不复制外部正文。
- 需要失败验证时放入 `tests/invalid/`，并纳入 Windows/Linux 检查脚本。

## 4. API 决策

- 优先组合已有公共接口；只有无法表达的稳定能力才新增 API。
- 新名称表达内容用途，不沿用消费者历史函数名作为公共兼容别名。
- 公共参数不得泄漏单一主题 token、私人路径或消费者字段。
- 公共 API 或关键边界变化时，更新 `docs/API.md`，必要时增加 ADR。

## 5. 包内回归

- 运行 Windows 或 Linux 完整测试，确认 PDF 正式目标和 HTML 实验目标均能编译。
- 渲染受影响示例，检查文字、间距、分页、页眉页脚和组件边界。
- 包内所有测试数据保持中性，可安全提交并进入 CI。

## 6. 外部消费者验证

- 消费者通过薄适配器完成旧调用签名和项目字段映射；不修改旧全局入口。
- 使用参数化脚本暂存当前包源码，再以消费者根目录执行真实编译：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/test-consumer.ps1 `
  -ConsumerRoot X:\path\to\consumer `
  -Entry path\to\main.typ
```

- 私人绝对路径只出现在本地命令参数中，不写入仓库。
- 对照迁移前基线检查页数、警告、关键页面和项目资源；CeTZ 等项目代码仍在消费者侧。

## 7. 文档更新

- 更新公共 API、示例、结构索引和当前方案。
- 把稳定边界与取舍归档到 `docs-agent/decisions/`。
- 若消费者目录职责或维护流程改变，再更新消费者自己的项目文档。

## 8. 版本发布

- 只有包内回归和外部消费者验证均通过后，才决定版本号和发布范围。
- 发布前复核隐私、许可证、字体和素材来源。
- 不通过移动既有标签覆盖历史发布；版本创建、标签和远端推送需单独确认。
