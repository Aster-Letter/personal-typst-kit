# 真实 handout 消费者迁移决议

状态：历史归档
最后整理：2026-07-14 01:35 (Asia/Shanghai)
当前权威方案：../CURRENT_PLAN.md

说明：本文件保留首次跨工作区 handout 迁移实验的边界决议。后续执行以当前权威方案为准。

## 背景

一个私有 Tutorial 工作区仍通过旧外壳和旧讲义组件编译真实课次 handout。迁移实验用于验证公共 handout profile 能否承接真实信息密度，并建立消费者驱动的模板演进流程。外部正文、身份代号、课程资料和图形代码不进入本仓库。

## 决议

- `handout`、`learning-objectives`、`worked-example`、`exercise` 和 `callout` 承接已有通用语义。
- 新增 handout 扩展 `response-area(rows:, label:, ruled:)`，表达可复用的学习者作答空间。
- 旧函数名只存在于 Tutorial 薄适配器，不作为 personal-typst-kit 公共兼容别名。
- 学生代号、小组代号、课时等消费者字段不加入通用 `meta`。
- CeTZ 图形、项目资源和路径解析继续由调用项目负责。
- 包内以中性示例进入 Windows/Linux CI；外部验证通过参数化本地脚本运行，不提交私人绝对路径。
- 本次只做工作树迁移实验，不创建版本、不移动既有标签、不推送远端。

## 验证门槛

- 包内 PDF 与实验 HTML 编译通过，新增作答区完成视觉检查。
- 外部未修改版本先建立 PDF 基线；迁移后使用同一消费者根目录重新编译并检查关键页面。
- 旧全局模板入口保持不变，消费者仅新增适配器并修改指定入口导入。

## 实验结果

- 未修改消费者与迁移消费者均编译为 9 页，分页数量保持稳定。
- 迁移版全部页面通过渲染检查；作答区、长题块、页眉页脚和消费者侧 CeTZ 图形无裁切或重叠。
- 真实编译暴露默认 JetBrains Mono 不一定存在的问题；正式支持的 Windows/Linux 改用可发现的 DejaVu Sans Mono，消费者恢复无警告编译。
- `worked-example` 与 `exercise` 在真实信息密度下表现可接受，本次不再扩大公共 API 或调整其默认视觉。
